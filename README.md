# JobBlast

Self-hosted, single-user, $0 job-application assistant. It aggregates real
postings from free job APIs and boards, scores them against your profile,
drafts a tailored resume-bullets-and-cover-letter pair with your local
Claude Code CLI, and tracks every application through to an outcome - while
you stay in the loop for every apply.

## Features

- **11 free job sources**: France Travail, Adzuna, Greenhouse, Lever,
  Himalayas, RemoteOK, Remotive, Arbeitnow, Yourator, TokyoDev, japan-dev
  (104.com.tw ships disabled - see `docs/CONFIG.md`).
- **Weighted-keyword scoring**, entirely config-driven: skills, target
  locations, and penalties (seniority, work authorization, off-target
  location) all live in `jobblast.config.json`, not in the code.
- **AI-tailored applications**: resume bullets and a cover letter per
  posting, generated by the local `claude -p` CLI - rides your existing
  Claude subscription, $0 marginal cost per letter. Works fine without the
  CLI too: you get a clean template letter instead of an AI-tailored one.
- **PDF export** of the cover letter, plus CV/cover-letter storage on the
  Profile page with automatic text extraction from an uploaded CV PDF.
- **Human-in-the-loop, always**: the app never submits anything on your
  behalf. Approving a match opens the employer's own posting for you to
  apply on, and only then does the tracker move past "prepared".
- **Application tracker** with a real status pipeline (approved → applied →
  responded → interview → offer/rejected) and follow-up reminders.
- **Optional AI Scout**: a headless Claude agent that searches your
  claude.ai job connectors (Indeed, Snagajob, Aquent, …) plus the live web
  for postings the structured APIs don't cover, verifies every URL, and
  feeds the results into the same pipeline. Off by default.
- **Optional Notion Inbox**: bridges a Notion database - typically fed by a
  scheduled claude.ai routine that runs while your machine is off - into
  the same pipeline. Off by default.
- **Self-hosted and quiet**: your own Postgres, your own machine, no
  telemetry, no account system, no recurring cost besides a Claude
  subscription you may already have.

## How it works

```
  sources  (11 free job APIs / boards, config-driven)
     │
     ▼
  scoring  (weighted keywords + target location + penalties)
     │        listings below the relevance threshold are dropped
     ▼
  review queue  (status: queued)
     │
     ▼
  AI tailoring  (claude -p → resume bullets + cover letter, every 30 min)
     │
     ▼
  review  (you: read "why this surfaced", edit the letter, Approve or Skip)
     │        Approve opens the posting - nothing is submitted automatically
     ▼
  apply  (you, on the employer's own site)
     │
     ▼
  tracker  (approved → applied → responded → interview → offer / rejected)
```

A background job refresh runs every 6 hours (aggregation across all enabled
sources) and an AI tailoring pass runs every 30 minutes, so the queue keeps
filling and drafts keep getting ready without you doing anything - you only
show up to review and click Apply.

## Quick start

```bash
git clone https://github.com/yaniswav/jobblast.git && cd jobblast
pnpm install && pnpm run setup      # copies .env / jobblast.config.json / cover-letter-template.txt from their examples
docker compose up -d && pnpm run db:push   # start Postgres, create the schema
pnpm run dev:api                    # terminal 1 - API on :5000
pnpm run dev:web                    # terminal 2 - frontend on :5173, open it in your browser
```

Then fill in your profile (Profile page: identity, target roles/locations,
master resume, CV/cover-letter upload) and edit `jobblast.config.json` to
match it - see `docs/CONFIG.md`. For a fully-narrated, non-expert walkthrough
(installing Node/pnpm/Docker included), see `docs/TUTORIEL.md` (French).

## Requirements

- **Node.js ≥ 24** (the API server's start script uses
  `--env-file-if-exists`, which needs Node 24+).
- **pnpm 10** (`corepack enable` or `npm i -g pnpm`; the repo refuses `npm`/`yarn`).
- **Postgres 16**, via `docker compose up -d` (see `docker-compose.yml`) or
  any Postgres instance you already run - just point `DATABASE_URL` at it.
- **Optional**: the [Claude Code CLI](https://docs.claude.com/en/docs/claude-code)
  (`claude`), installed and logged in, for AI-tailored letters, AI Scout,
  and the Notion Inbox bridge. Without it the app still works, just with
  template cover letters and those two optional sources disabled.

## Configuration

Nothing user-specific lives in the source tree. Three gitignored files (plus
one DB table) hold everything about *you*:

| Where | What |
|---|---|
| Postgres `profiles` row | Name, headline, target roles/locations, salary floor, master resume |
| `.env` | Secrets and ports - `DATABASE_URL`, job-source API credentials, `PORT` |
| `jobblast.config.json` | Letterhead, language rules, scoring rules, which job sources to poll |
| `config/cover-letter-template.txt` | The cover letter the AI tailoring pass imitates for structure/tone |

Full reference, every key documented: **[`docs/CONFIG.md`](docs/CONFIG.md)**.

## Free API keys

Two sources need a (free) API key; the rest need none.

- **France Travail** - register at [francetravail.io](https://francetravail.io/),
  create an application, subscribe it to the **"Offres d'emploi v2"** API
  (free access), then put the client ID/secret in `.env` as
  `FRANCETRAVAIL_CLIENT_ID` / `FRANCETRAVAIL_CLIENT_SECRET`.
- **Adzuna** - register a free app at
  [developer.adzuna.com](https://developer.adzuna.com/), then put the app
  ID/key in `.env` as `ADZUNA_APP_ID` / `ADZUNA_APP_KEY`.

Both are optional - disable them in `jobblast.config.json`
(`sources.franceTravail.enabled` / `sources.adzuna.enabled`) and the app
still aggregates from the nine sources that need no credentials at all.

## Running in production, locally

JobBlast is designed to run permanently on a machine you own - no cloud, no
hosting cost - with a single Node process serving both the API and the
already-built frontend.

- **Windows**: `deploy\build.ps1`, `deploy\start-jobblast.ps1`,
  `deploy\stop-jobblast.ps1`, `deploy\register-task.ps1` (auto-start at
  logon via a Scheduled Task).
- **Linux/macOS**: `deploy/build.sh`, `deploy/start-jobblast.sh`,
  `deploy/stop-jobblast.sh` (idempotent, PID-tracked), plus
  `deploy/jobblast.service.example` (systemd) and a launchd note.

Details, prerequisites, and log locations: **[`deploy/README.md`](deploy/README.md)**.

## Optional: AI Scout, Notion Inbox, cloud routines

Two optional sources extend coverage past the structured APIs by using the
`claude` CLI (AI Scout: your claude.ai job connectors + live web search;
Notion Inbox: a Notion database fed by a scheduled claude.ai routine that
can run while your machine is off). Both are off by default, config-driven,
and documented with setup steps in **[`docs/CONFIG.md`](docs/CONFIG.md)**
(reference) and **[`docs/TUTORIEL.md`](docs/TUTORIEL.md)** (`Options
avancées`, with generic, copy-pasteable scheduled-task prompts).

## Privacy

Everything runs on your own machine against your own Postgres database.
There's no telemetry, no account system, and no external service beyond the
job-source APIs you explicitly enable and (optionally) Anthropic via the
`claude` CLI you already use. User-specific files never enter the source
tree: `.env`, `jobblast.config.json`, `config/cover-letter-template.txt`,
and `data/` (uploaded CV/cover-letter PDFs, plus a couple of throttle-state
timestamp files) are all gitignored - see `.gitignore`.

## Legal / etiquette

JobBlast only talks to official public APIs (France Travail, Adzuna, with
your own registered credentials) and to a handful of unauthenticated,
publicly-documented JSON endpoints (Greenhouse, Lever, RemoteOK, Remotive,
Himalayas, Arbeitnow) or plain public listing pages (TokyoDev, japan-dev) -
no login walls, no CAPTCHA bypass, no scraping behind authentication.
Request volume is deliberately conservative (e.g. the Remotive fetcher caps
itself at one call per refresh cycle to respect their documented ~4/day
budget). AI tailoring only drafts; **the app never submits an application on
your behalf** - you always click through to the employer's own page. Review
each source's terms of use before enabling it.
